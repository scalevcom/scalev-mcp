Cara kerjanya

OAuth di depan, Scalev API yang berwenang.

Worker MCP hanya jadi gateway tipis. Worker memeriksa bahwa bearer OAuth ada, lalu meneruskannya apa adanya ke Scalev API. Autorisasi, scope, pemilihan bisnis, validasi, dan persistensi tetap di Scalev API.

Tidak ada data tersimpan di Worker

Tidak men-cache token, tidak menyimpan data merchant. Worker stateless.

Persetujuan eksplisit per bisnis

Setiap panggilan membawa business_unique_id. Claude tidak menebak antar bisnis.

Setiap panggilan diaudit

Machine API log di Scalev API mencatat caller, scope, request, status, dan request_id.

Izin

Scope yang akan diminta Claude.

Scope diberikan per bisnis saat consent. Anda bisa mencabut grant dari setting Scalev atau dari claude.ai. Tidak ada akses di luar yang Anda setujui.

Scope Yang bisa dilakukan Claude
page:list · page:readMelihat daftar landing page dan satu halaman.
page:createMembuat landing page baru, termasuk draft HTML Mode.
page:updateMengubah metadata, publish, atau unpublish landing page.
page:deleteMenghapus landing page (soft-delete).
order:list · order:readMelihat daftar order dan satu order.
order:createMembuat order baru atas nama Anda.
order:updateMengubah metadata, catatan, atau data pelanggan order.
order:change_statusMemindahkan order melewati workflow status.
order:create_awbMembuat atau membatalkan AWB pengiriman.

Keamanan & privasi

Dirancang untuk lolos review dan untuk produksi.

OAuth 2.1 + DCR

Claude registrasi otomatis (RFC 7591). PKCE S256 wajib. Refresh token rotasi tiap penggunaan.

Scope per bisnis

Scope granular (order:list, page:create, …) diberikan per bisnis.

Audit log tiap panggilan

Scalev API mencatat caller, scope, request, status, dan request_id yang bisa ditelusuri.

Siap disclosure
